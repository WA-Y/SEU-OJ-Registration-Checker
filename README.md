# SEU-OJ 报名核验

> 东南大学 OJ 新生赛报名信息的半自动化校对工具

用于新生赛报名表的半自动化校对：识别报名表 → 匹配 OIerDb 获奖数据 → 筛选「可能获奖」的新手组选手 → 人工确认 → 按校区分组导出结果；同时提供**台签、准考证、签到表**三种物料的一键批量生成，赛前现场可直接打印使用。

整份应用是一张纯前端页面，所有逻辑都在浏览器里跑完；`python run.py` 只是把它托管到本地。**不需要安装任何第三方 Python 库**，也能直接静态部署到任意网页空间。

在线网页：https://seu-oj-checker.app.workbuddy.host/?sharecode=MU34GM3VDK

## ✨ 特性

**报名核验**

- **鲁棒识别报名表**：自动扫描 Excel 各 sheet，模糊匹配「姓名 / 学号 / 一卡通 / QQ / 年级 / 组别 / 校区」等表头，支持组别多选、校区分列
- **自动匹配获奖数据库**：内置 OIerDb 快照（约 11 万姓名 / 12.8 万选手），按姓名 + 入学年份推算判断是否「可能获奖」，离线即用
- **同名智能区分**：按 UID 独立区分同名选手，标注「可能本人 / 同名非本人」，附完整获奖轨迹与年级
- **可视化工序**：待确认 / 已通过 / 草稿箱三栏，卡片式交互，支持搜索、撤销、回退
- **一键导出**：按「校区 × 组别」4 组输出 Excel，浏览器直接下载

**生成工具（左侧栏独立入口，与名单功能同级）**

| 工具 | 输入 | 输出 | 可自定义 |
|---|---|---|---|
| 🏷 台签生成 | 报名名单 + 账号密码表 | `.docx`（合并一份，或每人一份打包 zip） | 标题上下两行、文件名前缀 |
| 🎫 准考证生成 | 报名名单 + 账号密码表 | `.pdf`（A4 横向，2×2 排版，含校徽） | 文件名前缀 |
| 📝 签到表生成 | 报名名单 | `.pdf`（A4 纵向，左右两栏，每栏 20 行） | — |

- 台签按样例版式生成：一张 A4 = 同一人的上下面板，折起来就是双面台签，一页一人
- 准考证复刻样例排版：卡片尺寸、横线位置、logo 位置均按原模板比例还原
- 签到表列宽固定（序号 10% / 姓名 22% / 学号 28% / 签名 40%），人少不留空行，人多按每栏 20 行自动换页
- 所有文件都在浏览器本地读取与生成，不上传任何数据

## 🚀 快速开始

### 环境要求

- Python 3.8+（仅用于启动本地服务）
- Windows / macOS / Linux
- 现代浏览器（Chrome / Edge 80+，需支持 `DecompressionStream`）

### 安装与运行

```bash
git clone https://github.com/WA-Y/SEU-OJ-Registration-Checker.git
cd SEU-OJ-Registration-Checker

python run.py
```

启动后浏览器会自动打开 `http://127.0.0.1:8765`。无需 `pip install`，仓库已内置全部前端依赖（XLSX / JSZip / html2canvas / jsPDF）。

> 也可以直接双击 `web/index.html` 打开，或者在任意静态服务器上托管 `web/` 目录：功能完全一致，因为整份应用不含任何服务端依赖。

## 📖 使用流程

### 一、报名核验

1. **设置年份**（默认 2026）
2. **加载报名表**：点「选择文件…」选择报名 Excel，自动识别各列
3. **加载 OIerDb 数据库**：点一下即可，读取仓库内置快照（约 4MB，秒开）
4. **筛选匹配**：找出「报了新手组（大一/大二）但历史获过奖且年级对得上」的选手，进入「待确认」栏
5. **人工确认**：核对每个疑似获奖选手（可查看完整获奖详情），确认通过或取消资格
6. **导出结果**：按 4 组下载 Excel

### 二、台签 / 准考证 / 签到表

左侧栏「生成工具」区域点对应入口：

- **台签**：上传报名名单 + 账号密码表 →「检查匹配」核对配对结果 → 填标题两行 → 生成 docx
- **准考证**：上传报名名单 + 账号密码表 →「检查匹配」→ 预览 → 下载 PDF
- **签到表**：上传报名名单 → 生成 PDF

三者的表头都能自动识别（如「姓名 / 账号 / 密码 / 准入码」，账号列兼容「登录账号 / 用户名」等别名），匹配时按 姓名 → 学号 → 一卡通 逐级兜底。

## 🔄 更新获奖数据

仓库内置的 `web/data/*.json.gz` 是抓取时刻的快照，页面读取它做匹配，离线可用。要更新（例如新赛季数据发布后）：

```bash
python src/oierdb_fetcher.py
```

脚本会从 OIerDb 官方接口下载最新 `result.txt`（约 13MB），解析后重建 `web/data/oierdb_index.json.gz` 与 `web/data/oierdb_detail.json.gz`，同时把原始数据缓存到 `data/`（已 gitignore）。下载与解析都会打印进度。更新完刷新页面即可，无需重启服务。

## 🔍 筛选逻辑

- 报名人的大学入学年份由报名表年级解析（如「大一（26 级）」→ 2026）
- 若某人报了新手组（大一/大二）、名字在 OIerDb 获奖名单中、且推算的大学入学年份与报名年份之差 ≤ 1，则判定为「可能获奖」，需人工确认
- 专业组选手直接视为报名成功，不参与新手筛选
- **同名处理**：OIerDb 中存在多个同名者时，按 UID 独立区分，分别列出各人的入学年份轨迹，标注「可能本人 / 同名非本人」

## 📤 导出分组（4 组）

| 分组 | 说明 |
|---|---|
| 四牌楼校区_大一大二组 | 四牌楼校区的大一组 + 大二组 |
| 四牌楼校区_专业组 | 四牌楼校区的专业组 |
| 九龙湖校区_大一大二组 | 九龙湖校区的大一组 + 大二组 |
| 九龙湖校区_专业组 | 九龙湖校区的专业组 |

每个分组输出一份 `.xlsx`，包含姓名、学号、花名、一卡通号、手机号、QQ、年级、组别、校区。

> 若某位同学同时报名多个组别，会同时出现在对应的多个分组文件中。

├── legacy/                   # v1 服务端实现（读表/匹配/导出），仅作参考

### 关于 legacy/

最初版本把「读表 / 匹配 / 导出」都放在 Python 服务端（`legacy/server.py` 等）。v2 把这些逻辑整体搬到浏览器，好处是一份代码既能本地跑也能静态托管，且报名文件不经服务器中转。

`legacy/` 里的代码不参与运行，只作参考保留；若要单独运行，需 `pip install openpyxl`，并把 `legacy/` 与 `src/` 都加入 `sys.path`。

## ❓ 常见问题

- **「加载 OIerDb 数据库」没反应**：浏览器过旧（不支持 `DecompressionStream`），换 Chrome / Edge 80+。
- **数据想更新到最新**：页面不联网抓数据，运行 `python src/oierdb_fetcher.py` 重建快照后再刷新页面。
- **更新数据很慢**：`result.txt` 约 13MB，取决于网络；脚本会打印下载进度（MB）与解析状态。
- **识别不到某列**：报名表表头需包含「姓名 / 学号 / 一卡通 / QQ / 年级 / 组别 / 校区」等关键词，程序已做模糊匹配。
- **组别分散在多列**：程序会自动合并所有含「组别」的列，并拆分多选值（如「大一组, 专业组」）。
- **台签长姓名被裁切**：名牌子按 2–3 字姓名排满，4 字姓名会溢出，需要时可在 Word 里手动缩小字号。
